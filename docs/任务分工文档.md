## 三、后端任务（1 人 × 4 周）

### Phase 1：基础设施 + 核心数据链（Week 1-2）

| 子任务 | 内容 | 产出 |
|--------|------|------|
| 项目骨架 | 父 POM、common 模块（core/security/web/mq）、Docker Compose | 工程能启动 |
| 数据库 | 18 张表 DDL + 初始化脚本 + MyBatis 代码生成 | 库表就绪 |
| auth-service | 登录/登出/Token 刷新 + RBAC 6 角色 | 前端能登录 |
| file-service | 文件上传/下载/SHA-256 计算 | 前端能传图 |
| breeding-service | 养殖场 CRUD + 生猪档案 + 疫苗 + 出栏申报 + 产地检疫证明 | 第一批业务 API |
| gateway-service | 路由转发 + JWT 鉴权 + 限流 + 跨域 | 统一入口 |
| DemoDataInitializer | 启动时自动插入全链路模拟数据 | 前端开箱即用 |

> **里程碑**：Person A 可开始连调养殖管理页面

### Phase 2：屠宰 + 分割配送（Week 3）

| 子任务 | 内容 |
|--------|------|
| slaughter-service | 入场查验 + 宰前/宰后检验（含脏器检查 JSON）+ 瘦肉精检测 + 检疫合格盖章 |
| distribution-service | 胴体批次 + 分割拆分（树状结构）+ 冷链运输 + 温度打卡 + 门店签收 |

> **里程碑**：Person A 可连调屠宰 + 分割配送页面

### Phase 3：区块链 + 销售（Week 4）

| 子任务 | 内容 |
|--------|------|
| blockchain-service | 适配器模式（FISCO BCOS / Fabric）+ Solidity 合约部署 + 异步上链（RabbitMQ）+ 验真接口 |
| sales-service | 二维码批量生成 + 销售激活 + 销售记录 + 过期预警（定时任务）+ 召回管理 |

> **里程碑**：Person B 可连调销售管理页面 + 区块链验真

### Phase 4：追溯 + 小程序接口（Week 5）

| 子任务 | 内容 |
|--------|------|
| trace-service | 上下游追溯 + 秒级反查 + 举报管理 |
| consumer API | 扫码溯源 / 安心购 / 一键验真接口（小程序专用） |

> **里程碑**：两人可连调追溯页面 + 小程序全部接口

## 八、协作规范

| 事项 | 约定 |
|------|------|
| **接口定义优先** | 后端先出 Swagger 文档，前端按文档 Mock 数据并行开发 |
| **B 先出通用组件** | Person B 第一周完成 10 个通用组件，Person A 从第二周起直接引用 |
| **A 定架构规范** | 路由结构、Pinia Store 接口设计、API 模块划分由 A 先定，B 照规范执行 |
| **Git 分支** | `feat/web-framework`（A）、`feat/web-business`（B）、`feat/miniapp-core`（A）、`feat/miniapp-features`（B）、`feat/xxx-service`（后端） |
| **每日站会** | 10 分钟同步进度+阻塞点 |
| **代码评审** | 每个联调节点后进行交叉 Review |
| **Mock 方案** | 前端使用 Apifox / Mock.js 本地 Mock，后端 Phase 1 同步出 `DemoDataInitializer` |
| **Demo 数据** | 后端 Phase 1 完成初始化脚本，系统启动即有完整模拟数据链路 |
