# 架构知识图谱 + 自然语言操作

> 需求来源：Jaeden 2026-11-18
> 「系统架构比较复杂，能不能转成知识图谱，然后用自然语言来操作系统」
> 落地时间：2026-11-19
> 代码位置：`backend/ai-service/src/main/java/com/pork/ai/graph/`

---

## 一、先说清楚做了什么、没做什么

**做到了**：在管理后台说一句话，系统自己找到对应接口、补齐参数、带你的身份去执行，把结果以卡片形式返回。

```
「把这条召回单标记为已完成」
   ↓
① 命中 PUT /sales/recalls/{id}/status（0.58）
   ↓
② 千问：id=12，status=4
   ↓
③ 缺 status → 追问「要标记成哪个状态？（2 已发起 / 3 收运中 / 4 已完成）」
   ↓
④ 用户补「4」→ 参数齐 → 写操作 → 弹「确认执行」
   ↓
⑤ 点确认 → 经网关带用户 JWT 调用 → 返回结果卡片
```

**没做的，别期待**：

- **没有 Neo4j**。图是内存里的邻接关系 + 倒排索引，重启从 classpath 种子重建。理由见第五节。
- **没有向量检索**。千问只当 chat 模型用，没有 embedding 接口。检索是词法打分，可解释、可复现。
- **不支持跨接口编排**。一句话只做一件事。说「查出退货单再导出」会被拆成两次对话。
- **写操作默认全关**。只有 `GET` 能直接跑，其余要在 `application.yml` 里按 operationId 逐个放开。

## 二、四层结构

### 第一层：建图（离线 + 运行时）

图谱节点只有两类，刻意做得很扁：

| 节点 | 例子 | 来源 |
|---|---|---|
| Module（模块） | `mod:breeding-service:养殖场管理` | Swagger `@Tag` |
| Operation（操作） | `op:breeding-service:GET:/farms` | `@GetMapping` + 路径 |
| Param（参数） | `current(Long, 可选, 默认1)` | `@RequestParam` / `@PathVariable` / `@RequestBody` |

**两个数据源，各有各的用处**：

| 源 | 怎么做 | 优点 | 缺点 |
|---|---|---|---|
| 静态扫描 | `python scripts/build-arch-graph.py` | 一个服务都不用起就能建图 | 拿不到泛型、默认值、body 嵌套结构 |
| OpenAPI | `POST /api/v1/ai/admin/graph/rebuild` | Spring 自己生成的 schema，准 | 要求目标服务在线 |

扫描器会输出 `backend/ai-service/src/main/resources/arch-graph-seed.json`。当前规模：

```
39 个模块 / 218 个接口 / 10 个服务
其中 53 个标记为 internal（内部接口，AI 不执行）
```

**internal 怎么判定**：不能只看类名。不少 Controller 把 `/internal` 写在方法级注解上（如 `sales-service` 的 `GET /sales/internal/products`），类名里根本没有 `internal` 字样。早期版本只按类名判，漏了 8 个接口 —— 这些服务间接口因此被当成「可执行」，等于绕过了业务权限校验。现在扫描器按**路径段**判定，`ApiOperation` 的构造器里再按 `path`/`gatewayPath` 兜底纠正一次，种子、运行时 OpenAPI、手写测试数据三者的结论一致。

**为什么要 `gatewayPath` 这个字段**：网关的 `StripPrefix` 每个服务不一样（breeding 是 3，其余是 2），auth 和 trace 的服务内路径本身就带一级（`/auth`、`/dashboard`）。这个前缀无法自动推导，只能在 `application.yml` 里写死。写在建图时而不是执行时，是因为执行时算错一次就是 404，而且还不好查。

### 第二层：检索（GraphRAG 路由）

用户原话 → 候选接口（默认 8 个）。

**为什么不用向量**：千问是 chat 模型，没有 embedding 接口。自己搭一个 embedding 服务只为了检索 200 个接口，投入产出不成比例。200 个接口的词法检索，好好调权重比向量检索更可控 —— 而且出问题时能说清楚「为什么选中它」。

**分词**：中文 2-gram + 英文小写 + camelCase 拆分 + 复数归一。

```
「退货单」→ [退货, 货单, 退货单]
「warnings」→ [warnings, warning]
「safeBuy」→ [safebuy, safe, buy]
```

**字段权重**（决定排序的关键）：

| 来源 | 权重 | 理由 |
|---|---|---|
| summary | 3.0 | 人写给人看的短句，最能代表意图 |
| 模块名 / 描述 | 2.0 / 1.0 | 同模块收敛，避免跨服务误配 |
| 路径段 | 2.0 | `/return-order/export` 里的 `return-order` 很关键 |
| 方法名 | 1.5 | 没写 `@Operation` 时的唯一线索 |
| 参数名 | 1.0 | 只能辅助确认，不能决定选哪个 |

**三处必要的修正**（都是实测踩出来的）：

1. **动词与 HTTP 方法对齐**
   说「删除」时 DELETE 加权 1.4，其它方法乘 0.65。不加这条，「查一下各养殖场」的候选里会混进 `DELETE /farms/{id}`。

2. **internal 接口降权 0.4**
   `POST /breeding/internal/ingest/farm-batch` 的路径里同时有 `farm` 和 `batch`，说「新建养殖场」时它会排第一。降权后才让位给真正的 `POST /farms`。

3. **归一化用饱和函数 `raw/(raw+10)`，不是「除以本次最高分」**
   除以最高分会让任何一次孤立命中都显示成 1.0。实测「看看有哪些过期的产品」曾把区块链迁移接口顶成满分 100%，界面看起来像万分确定，实际只有一个词碰上了。

**同义词表在 `application.yml` 里**，加一个说法不用发版：

```yaml
synonyms:
  "卖": ["sale", "sell", "retail"]
  "过期": ["expire", "warning"]
  "召回": ["recall"]
```

**实测效果**（`/ai/graph/search` 可复现）：

| 用户说法 | Top1 | 分数 |
|---|---|---|
| 查一下这个月各养殖场的存栏量 | GET /farms/page | 0.85 |
| 看看有哪些过期的产品 | GET /sales/warnings | 0.67 |
| 今天卖了多少猪肉 | POST /sales/records | 0.58 |
| 查询批次 P20261101 的检疫证明 | GET /pigs/{pigId}/quarantine-cert | 0.88 |
| 把这条召回单标记为已完成 | PUT /sales/recalls/{id}/status | 0.58 |
| 把上个月张三负责的退货单导出来 | GET /distribution/return-pool | 0.64（项目里没有导出接口） |

### 第三层：千问槽位填充

把 8 个候选按 `promptLine()` 排成一行一个，交给千问，要求它输出：

```json
{"operation":"op:...","slots":{"startDate":"2026-10-01"},"question":"...","reason":"..."}
```

**千问只做两件事：在候选里选一个、把自然语言拆成参数值。**

它不做的事，以及为什么：

| 不给它做的事 | 原因 |
|---|---|
| 找接口 | 检索是代码算的，可复现；模型找接口每次结果都可能不同 |
| 判断参数够不够 | 后端对比 schema 算。模型说「齐了」不算数 |
| 拼 URL | 只认 operationId，路径从图谱取。模型控制不了 URL，就诱导不了服务去访问别处 |
| 决定要不要执行 | 写操作必须用户点确认 |

**模型输出的处理**：

- 抽 JSON 用括号配平（它经常加「好的，这是结果：」或裹 ```json）
- `operation` 必须能在候选里找到，找不到就当成没匹配 —— 不猜
- 参数按 schema 白名单过滤，多出来的键直接丢
- 缺哪些必填由后端算，不看模型怎么说

**千问不可用时的降级**：选检索第一名，参数全部留给追问。故意不尝试规则抽时间/人员 —— 正则抽出来的时间十次错三次，而错参数比没参数糟得多（会查到别人的数据，或者静默查空）。

### 第四层：安全执行

`ActionExecutor` 是唯一有副作用的组件，所以它默认很保守。

**五道闸**：

| 闸 | 规则 | 挡住什么 |
|---|---|---|
| 方法是白名单 | 默认只有 `GET` | 模型被提示注入后删数据 |
| 写操作要点名 | `allowed-write-operations` 里逐个列 | 误操作 |
| 服务黑名单 | `auth-service` 一律不执行 | 改密码、删用户 |
| 路径黑名单 | `/system` `/internal` `/ingest` `/ai/` | 系统管理、内部接口 |
| 参数白名单 | 只取 schema 里有的键 | 模型自己塞 `userId` 之类 |

**路径黑名单是按「路径段」匹配的，不是 `startsWith`。** 黑名单写 `/internal`，而 `/sales/internal/products` 并不以它开头 —— 用 `startsWith` 会放行一大批内部接口。现在同时匹配开头和中间完整段（`/administration/list` 这种只是字符串像的不会被误杀），并且 `path` 和 `gatewayPath` 都看一遍：ai-service 自己的接口在本地是 `/graph/stats`，只有拼上网关前缀后才落在 `/ai/` 下，靠本地路径是拦不住的（拦不住就意味着对话接口能被自己无限套娃调用）。

**关键设计：经网关转发，透传用户 JWT。**

```
ai-service ──Authorization: Bearer <用户令牌>──> gateway:8080 ──> 目标服务
```

不走直连，因为直连的话 ai-service 就得自己决定「这个用户是谁」——那才是越权的开始。走网关，JWT 校验、`X-User-*` 注入、令牌黑名单全部复用现有那套，`ai-service` 不制造身份。

**审计**：每一次执行都落一条结构化日志。

```
ai_action user=zhangsan op=op:sales-service:GET:/sales/records
          method=GET path=/sales/records status=200 cost=86ms params={...}
```

密码类字段显示为 `***`。

**限频**：默认 20 次/分钟/用户，滑动窗口，内存实现。

## 三、接口

全部需要登录（网关对 `/api/v1/ai/**` 除 consumer/health 外都要求 JWT）。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/ai/action/chat` | 发一句话，返回结构化结果。请求体 `{"text":"...","conversationId":"..."}` |
| POST | `/api/v1/ai/action/confirm` | 写操作二次确认。请求体只传 `conversationId`，参数留在服务端 |
| GET | `/api/v1/ai/graph/stats` | 图谱规模、各服务接口数 |
| GET | `/api/v1/ai/graph/search?q=&topK=` | 检索调试，看命中词、分数、`executable` 与 `denyReason` |
| POST | `/api/v1/ai/admin/graph/rebuild` | 重建图谱（需 SUPERVISOR/ADMIN） |

> 请求字段是 `text` 不是 `message`。字段名写错时 Jackson 会静默忽略，接口返回「请输入你想做的事」，看起来像检索失败 —— 排查时先看一眼这里。

### chat 的返回

```json
{
  "phase": "NEED_SLOT",
  "conversationId": "9f2b...",
  "operation": {
    "id": "op:sales-service:PUT:/sales/recalls/{id}/status",
    "summary": "recallStatus", "method": "PUT",
    "path": "/sales/recalls/{id}/status",
    "module": "召回管理", "service": "sales-service"
  },
  "slots": { "id": 12 },
  "missing": [
    { "name": "status", "type": "Integer", "hint": "数字" }
  ],
  "question": "要标记成哪个状态？2 已发起 / 3 收运中 / 4 已完成",
  "answer": "要标记成哪个状态？...",
  "execution": null,
  "candidates": [ ... ]
}
```

`phase` 五种：

| phase | 含义 | 前端该做什么 |
|---|---|---|
| `UNSUPPORTED` | 没找到对应功能 | 显示 `question`，引导换个说法 |
| `NEED_SLOT` | 缺必填参数 | 把 `missing` 渲染成输入提示 |
| `READY` | 参数齐了，是写操作 | 显示「确认执行」按钮 |
| `EXECUTED` | 已执行 | 渲染 `execution.data` |
| `FAILED` | 执行失败或被策略拒绝 | 显示 `execution.error` 或 `answer` |

## 五、几个刻意的取舍

### 为什么不用 Neo4j

节点 250 个、关系不到 1000 条。Neo4j 的内存占用、运维成本、容器编排复杂度，换来的查询能力在这个量级完全用不上。而且我们最需要的不是图遍历，是**文本 → 节点**的检索，这恰恰是 Neo4j 不擅长的部分。

真需要图数据库的信号是：要回答「改这个接口会影响哪些下游流程」这种多跳问题，且关系有几十万条。现在没有。

### 为什么检索不用 LLM 直接选

200 多个接口塞不进上下文（就算塞进，随上下文变长准确率下降明显）。先收敛到 8 个再让模型选，是唯一能在本地 27B 模型上稳定工作的做法。

### 为什么写操作默认全关

因为模型的错误是不可预测的。读错了顶多看到不该看的数据（还有下游鉴权兜底），写错了是要回溯的。默认关闭的代价是多改一行配置，收益是「提示注入也删不掉数据」。

### 为什么会话放内存

会话只是补参数的临时状态，TTL 10 分钟，丢了用户重说一句就好。放 Redis 要多一个依赖、多一个故障点，换来的只是多实例共享 —— 当前单实例用不上。真要扩容，`ActionSessionStore` 换实现即可，对外只有四个方法。

## 六、已知限制

1. **检索对「项目里没有的功能」无能为力**
   说「导出退货单」，系统里没有导出接口，它只能在相近的候选里挑一个。
   这时千问通常会返回 `operation: null` 并说明 —— 比硬凑一个正确。

2. **不做跨接口编排**
   「查出 A 然后拿结果去做 B」需要两次对话。真正的 Agent 编排（ReAct / function calling 循环）是下一步，不是这一版。

3. **日期换算是模型算的**
   「上个月」由千问按 prompt 里注入的今天换算。实测基本正确，但跨年边界（12 月说「上个月」）建议复核。

4. **静态扫描拿不到泛型参数**
   `@RequestParam List<Long> ids` 扫出来是 `List<Long>`，OpenAPI 重建后才是真实 schema。所以要精确参数，跑一次 rebuild。

5. **`auth-service` 整个被拉黑**
   哪怕只是想「查一下有多少用户」也不执行。这类需求应该走系统管理页面。

6. **写操作被过滤后，可能落到语义较远的只读接口**
   候选列表在交给模型之前就用执行器过滤了一遍（`buildCandidates` 里 `isExecutable`），
   `POST /sales/records` 这种没点名的写操作模型根本看不到。于是「今天卖了多少猪肉」
   这条，检索 Top1 本来是 `POST /sales/records`（0.58），被过滤后降级路径挑中的是
   `GET /sales/recalls/affected-stores` —— 接口本身没问题，但答的不是用户问的问题。
   接上真千问之后它会倾向于返回 `operation: null` 并说明原因，比降级路径好；
   但要彻底解决，得让「因写操作被拒」这件事显式回到模型和用户面前，而不是静默换一个。
   当前的处理方式是：确实要用就先把接口 id 加进 `ai.action.allowed-write-operations`。
   另外，凡是降级（`Decision.fromModel() == false`）产生的回答，前面都会挂一句
   「当前连不上大模型，这是按关键词匹配选出来的接口，可能不是你想要的」——
   宁可让用户怀疑结果，也不要让他把另一件事的数据当成自己要的。

7. **执行链路没有跑过完整端到端**
   本地验证覆盖到「检索 → 选接口 → 算缺参 → 追问」和「降级 → 实际发请求」，
   但下游服务（`sales-service` 等）、网关、Nacos 都没起，所以「经网关带 JWT 真正改到数据」
   这一段只验到错误分支（`Connection refused`）。上线前必须在联调环境补一次。

---

## 七、后续可以怎么扩

1. **接 function calling**：千问支持 tools 的话，把候选接口转成 tool schema，让模型自主多轮调用，就能做跨接口编排。
2. **加表结构**：现在图谱只有接口层，没有「这个接口读写哪张表」。补上之后能回答「改这张表会影响哪些接口」。
3. **接 Neo4j**：等到需要多跳推理、或者要把非结构化文档（制度、SOP）也挂进图里时。
4. **按角色裁剪候选**：现在候选是全量的，靠下游鉴权兜底。可以按 `X-User-Role` 先过滤，少让模型看见它无权用的接口。
