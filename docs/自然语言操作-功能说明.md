# 猪肉溯源系统：用一句话操作后台

> 这次更新的内容：后台的 AI 助手从「只能聊天」变成「能干活」。
> 你在对话框里说一句中文，它自己找到对应的功能，把结果查出来给你看。

---

## 以前 vs 现在

以前查一个数据，得先知道它藏在哪个菜单里。

| 想知道什么 | 以前怎么做 | 现在怎么做 |
|---|---|---|
| 某头猪的产地检疫证明 | 找到「检疫证明」页面 → 选猪只 → 输编号 → 点查询 | 打一句「查看 1 号猪的产地检疫证明」 |
| 哪些产品快过期了 | 知道要去「销售预警」里翻 | 打一句「看看有哪些过期的产品」 |
| 这个月各养殖场存栏多少 | 进养殖场列表 → 逐个看 → 自己数 | 打一句「查一下这个月各养殖场的存栏量」 |
| 上个月张三负责的退货单 | 进退货池 → 按人筛 → 按时间筛 | 打一句「把上个月张三负责的退货单找出来」 |

**不用记菜单、不用记字段名、不用记接口路径。** 说人话就行。

---

## 它现在能做的四件事

**1. 听懂人话，自己找功能**

系统里有 218 个功能点分散在 10 个服务里。你说「看看过期的产品」，
它能自己找到「销售预警」那个功能，不需要你说出功能的名字。

**2. 信息不全的时候会问你**

你只说「查看产地检疫证明」，没说哪头猪，它会回一句：

> 要查看产地检疫证明，还需要补充：pigId（数字）。

你补一句「1」就行，不用重新组织一整句话。

**3. 记得刚才聊到哪儿**

同一个对话里，前面说的事它记着。补完参数直接出结果，不用从头再来一遍。

**4. 每次都告诉你它理解成了什么**

结果卡片上会写清楚它理解的是哪个功能 —— 中文名、请求方式、接口地址都列出来。
理解得不对你一眼就能看出来，不会稀里糊涂给你一个错的数据。

## 一个真实的例子

你说：

> 查看 1 号猪的产地检疫证明

它返回：

```
[已执行]  查看产地检疫证明   GET  /pigs/{pigId}/quarantine-cert
已执行「查看产地检疫证明」。共 1 条。

执行成功                              HTTP 200 · 87 ms
{
  "pigId": 1,
  "certNo": "JY20261101001",
  ...
}
```

如果只说「查看产地检疫证明」，卡片会变成：

```
[需要补充信息]  查看产地检疫证明   GET  /pigs/{pigId}/quarantine-cert
要查看产地检疫证明，还需要补充：pigId（数字）。
还需要  [pigId（数字）]
```

## 现在还做不到的事（说清楚，免得误会）

**1. 不能替你改数据。**

新建养殖场、修改检疫结果、删除批次、审批召回单 —— 这些**一律不执行**。
你说了它也不会动手，只会告诉你「没找到能对应这句话的功能」，或者给你一个相近的查询结果。

这是刻意的设计：AI 猜错一个字，改错的就是生产数据。第一版只开放「查」，等用稳了再一个一个放开「改」。

**2. 不会连着做两件事。**

「先查出 A，再拿 A 的结果去做 B」这种要分两次说。它现在一次只干一件事。

**3. 有些功能永远不让 AI 碰。**

登录注册、用户权限管理这些，以及系统内部服务之间互相调用的接口，
对 AI 是彻底关闭的 —— 防止有人用一句话绕过权限。

**4. 日期要靠它自己换算。**

你说「上个月」，它按今天推算。跨年的时候（比如 1 月说「上个月」）建议自己核对一下结果。

## 正式上线前还需要一步

现在这套东西在本地验证通过（功能能找到、参数能追问、拦截规则正确），
但**还没有在真实环境跑通完整链路** —— 需要把网关和几个业务服务一起起来，
用真实账号走一遍「查一条真数据」和「经用户身份权限校验」的流程。

这一步预计很快，属于联调，不是开发。

---

## 怎么用

打开后台，**右下角有一个蓝色的「AI 助手」悬浮按钮**，任何页面都能点。点开之后，
顶部切到「**操作**」模式。

> **只有监管员（SUPERVISOR）和管理员（ADMIN）账号能看到这个按钮。**
> 普通账号登录是看不到入口的 —— 不是坏了，是权限控制。

底下给了几个常用说法的快捷按钮，也可以直接打字。

> 「操作」和「问答」是两个独立模式，互不干扰，消息不会串。
> 问答模式还是原来的纯聊天，不会动数据。
