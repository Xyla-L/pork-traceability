## 二、微服务模块划分

| 服务名称 | 职责 | 端口 |
|---------|------|------|
| `gateway-service` | API 网关，统一鉴权、路由 | 8080 |
| `auth-service` | 登录认证、角色权限、CA证书管理 | 8081 |
| `breeding-service` | 养殖免疫模块（耳标、疫苗、出栏、产地检疫） | 8082 |
| `slaughter-service` | 屠宰检疫模块（入场查验、宰前/宰后检验、瘦肉精检测） | 8083 |
| `distribution-service` | 分割配送模块（批次拆分、冷链运输、门店签收） | 8084 |
| `sales-service` | 市场销售模块（扫码销售、过期预警、召回） | 8085 |
| `trace-service` | 应急追溯模块（批次反查、举报处理） | 8086 |
| `blockchain-service` | 区块链适配层（上链、查询、验真） | 8087 |
| `file-service` | 文件上传下载、SHA-256计算 | 8088 |

### 3.2 核心表结构

#### 3.2.1 养殖免疫

```sql
-- 生猪个体表
CREATE TABLE pig_individual (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    ear_tag_no      VARCHAR(32)  NOT NULL UNIQUE COMMENT '耳标号',
    farm_id         BIGINT       NOT NULL COMMENT '养殖场ID',
    breed           VARCHAR(32)  COMMENT '品种',
    birth_date      DATE         COMMENT '出生日期',
    pen_no          VARCHAR(16)  COMMENT '圈舍编号',
    source          VARCHAR(64)  COMMENT '来源（自繁/外购）',
    status          TINYINT      DEFAULT 1 COMMENT '状态:1在养,2已出栏,3已屠宰,4异常',
    create_time     DATETIME     DEFAULT CURRENT_TIMESTAMP,
    update_time     DATETIME     DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_farm (farm_id),
    INDEX idx_status (status)
) COMMENT '生猪个体';

-- 疫苗注射记录表
CREATE TABLE vaccine_record (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    pig_id          BIGINT       NOT NULL COMMENT '关联 pig_individual.id',
    vaccine_name    VARCHAR(64)  NOT NULL COMMENT '疫苗名称（如:猪瘟疫苗、口蹄疫疫苗）',
    batch_no        VARCHAR(32)  NOT NULL COMMENT '疫苗批次号',
    inject_time     DATETIME     NOT NULL COMMENT '注射时间',
    dosage          VARCHAR(16)  COMMENT '剂量',
    operator        VARCHAR(32)  NOT NULL COMMENT '操作人姓名',
    file_ids        JSON         COMMENT '上传的凭证文件ID列表 ["f_xxx"]',
    create_time     DATETIME     DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_pig (pig_id)
) COMMENT '疫苗注射记录';

-- 出栏申报表
CREATE TABLE slaughter_apply (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    pig_id          BIGINT       NOT NULL UNIQUE COMMENT '关联 pig_individual.id',
    apply_no        VARCHAR(32)  NOT NULL UNIQUE COMMENT '申报编号',
    apply_time      DATETIME     NOT NULL COMMENT '申报时间',
    weight_kg       DECIMAL(6,1) COMMENT '出栏体重(kg)',
    target_slaughterhouse VARCHAR(128) COMMENT '目标屠宰场名称及地址',
    approval_status TINYINT      DEFAULT 0 COMMENT '审批状态:0待审,1通过,2驳回',
    approval_time   DATETIME     COMMENT '审批时间',
    approver        VARCHAR(32)  COMMENT '审批人',
    create_time     DATETIME     DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_status (approval_status)
) COMMENT '出栏申报';

-- 产地检疫证表
CREATE TABLE quarantine_certificate (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    pig_id          BIGINT       NOT NULL COMMENT '关联 pig_individual.id',
    cert_no         VARCHAR(32)  NOT NULL UNIQUE COMMENT '检疫证明编号',
    issue_org       VARCHAR(128) NOT NULL COMMENT '签发机构',
    issue_time      DATETIME     NOT NULL COMMENT '签发时间',
    valid_until     DATE         COMMENT '有效期至',
    inspector       VARCHAR(32)  COMMENT '官方兽医',
    ca_signature    TEXT         NOT NULL COMMENT '签发机构CA数字签名',
    file_id         VARCHAR(64)  NOT NULL COMMENT '检疫证原件文件ID',
    content_hash    CHAR(64)     NOT NULL COMMENT '证照内容SHA-256哈希',
    create_time     DATETIME     DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_cert_no (cert_no)
) COMMENT '产地检疫证明';
```

#### 3.2.2 屠宰检疫

```sql
-- 入场查验表
```

#### 3.2.3 分割配送

```sql
-- 胴体批次表
CREATE TABLE carcass_batch (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    batch_no        VARCHAR(32)  NOT NULL UNIQUE COMMENT '胴体批次号',
    pig_ids         JSON         NOT NULL COMMENT '包含的生猪ID列表 [1,2,3]',
    total_weight_kg DECIMAL(8,1) COMMENT '总重量(kg)',
    create_time     DATETIME     DEFAULT CURRENT_TIMESTAMP,
    operator        VARCHAR(32)  COMMENT '操作人'
) COMMENT '胴体批次';

-- 分割批次表（记录白条猪→分割肉的拆分关系）
CREATE TABLE split_batch (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    batch_no        VARCHAR(32)  NOT NULL UNIQUE COMMENT '分割批次号',
    parent_batch_id BIGINT       COMMENT '父批次ID (carcass_batch.id)，形成树状结构',
    split_level     TINYINT      DEFAULT 1 COMMENT '拆分层级:1胴体,2二分体,3分割肉,4零售包装',
    product_name    VARCHAR(64)  NOT NULL COMMENT '产品名称（如:前腿肉、五花肉、排骨）',
    weight_kg       DECIMAL(6,1) COMMENT '重量(kg)',
    package_count   INT          COMMENT '包装数量',
    split_time      DATETIME     NOT NULL COMMENT '分割时间',
    workshop        VARCHAR(64)  COMMENT '分割车间',
    operator        VARCHAR(32)  COMMENT '操作人',
    file_ids        JSON         COMMENT '分割车间现场照片/视频截图',
    content_hash    CHAR(64)     COMMENT '分割记录SHA-256哈希',
    create_time     DATETIME     DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_parent (parent_batch_id),
    INDEX idx_batch (batch_no)
) COMMENT '分割批次';

-- 冷链运输表
CREATE TABLE cold_chain_transport (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    transport_no    VARCHAR(32)  NOT NULL UNIQUE COMMENT '运单号',
    split_batch_id  BIGINT       NOT NULL COMMENT '关联 split_batch.id',
    vehicle_no      VARCHAR(16)  NOT NULL COMMENT '车牌号',
    vehicle_type    VARCHAR(32)  COMMENT '车辆类型/吨位',
    driver_name     VARCHAR(32)  COMMENT '司机姓名',
    driver_phone    VARCHAR(16)  COMMENT '司机电话',
    origin          VARCHAR(128) COMMENT '起运地',
    destination     VARCHAR(128) COMMENT '目的地',
    depart_time     DATETIME     COMMENT '发车时间',
    arrive_time     DATETIME     COMMENT '到达时间',
    status          TINYINT      DEFAULT 1 COMMENT '1待发,2在途,3已送达,4异常',
    create_time     DATETIME     DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_status (status)
) COMMENT '冷链运输';

-- 冷链温度记录表
CREATE TABLE temperature_log (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    transport_id    BIGINT       NOT NULL COMMENT '关联 cold_chain_transport.id',
    record_time     DATETIME     NOT NULL COMMENT '记录时间',
    temperature     DECIMAL(4,1) NOT NULL COMMENT '温度(℃)',
    is_abnormal     TINYINT      DEFAULT 0 COMMENT '是否异常:1是,0否',
    recorder        VARCHAR(32)  COMMENT '记录人（手动打卡录入）',
    create_time     DATETIME     DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_transport_time (transport_id, record_time)
) COMMENT '温度记录';

-- 门店签收表
CREATE TABLE store_receipt (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,

    store_name      VARCHAR(128) NOT NULL COMMENT '门店名称',
    receipt_time    DATETIME     NOT NULL COMMENT '签收时间',
    receiver        VARCHAR(32)  NOT NULL COMMENT '签收人',
    qty_check       TINYINT      DEFAULT 1 COMMENT '数量核验:1一致,0差异',
    temp_check      TINYINT      DEFAULT 1 COMMENT '温度核验:1合格,0异常',
    receipt_photo   JSON         COMMENT '签收照片文件ID',
    e_signature     TEXT         COMMENT '签收人电子签名',
    content_hash    CHAR(64)     COMMENT '签收记录SHA-256哈希',
    create_time     DATETIME     DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_store (store_id),
    INDEX idx_transport (transport_id)
) COMMENT '门店签收';
```

#### 3.2.5 应急追溯 & 通用

```sql
-- 区块链存证记录表（本地镜像）
CREATE TABLE blockchain_record (
```

```solidity
    mapping(string => SlaughterInspect) private slaughterInspects;

    event BatchSplitStored(string indexed batchNo, string parentBatchNo);
    event StoreReceiptStored(string indexed transportNo, string storeId);
    event SaleActivated(string indexed qrCode, uint256 timestamp);
    event RecallPublished(string indexed recallNo, uint256 timestamp);

    function storeQuarantineCert(
        string calldata certNo,
        string calldata issueOrg,
        string calldata caSignature,
        string calldata contentHash
```

### 4.2 存证点与上链时机

| 序号 | 存证点 | 上链时机 | 存证内容 | 关联表的 `content_hash` |
|------|--------|----------|----------|------------------------|
| 1 | 产地检疫 | 检疫证签发后 | `cert_no` + `issue_org` + `ca_signature` + 证照内容哈希 | `quarantine_certificate.content_hash` |
| 2 | 屠宰双检 | 宰后检验完成且瘦肉精检测合格后 | 双检报告哈希 + 兽医电子签章 | `slaughter_inspection.content_hash` |
| 3 | 批次分割 | 每次分割操作完成 | 分割批次号 + 父批次号 + 产品名称 + 重量 + 内容哈希 | `split_batch.content_hash` |
| 4 | 门店签收 | 签收人电子签名完成 | 运单号 + 门店ID + 签收哈希 + 签名 | `store_receipt.content_hash` |
| 5 | 销售激活 | 消费者首次扫码（或上架时激活） | 二维码 + 批次号 + 激活时间 | `retail_sale.product_qr_code` |
| 6 | 召回指令 | 召回令发布时 | 召回编号 + 召回范围哈希 + 原因 | `recall_order.block_hash` |

### 4.3 一键验真流程

```
消费者扫码 → 获取产品二维码
    │
    ▼
后端查询该二维码对应的完整溯源链路数据
    │
    ├── 从MySQL获取：养殖、屠宰、分割、配送、销售的全部业务数据
    ├── 从本地FS获取：相关证书、报告、照片、视频截图
    │
    ▼
前端展示溯源信息页面
    │
    ▼ (用户点击"一键验真")
后端执行验真：
    │
    ├── 1. 对页面展示的每条存证数据计算SHA-256
    ├── 2. 调用区块链合约 verifyIntegrity(bizKey, computedHash)
    ├── 3. 逐条比对：若全部匹配 → ✅ 区块链已验证
    │     若任一不匹配 → ⚠️ 数据可能被篡改
    │
    ▼
返回验真结果给前端展示
```

### 7.2 上链流程图（以屠宰双检为例）

```
  官方兽医提交检验报告
        │
        ▼
  slaughter-service 接收请求
        │
        ├── 1. 数据校验（字段完整性、权限）
        ├── 2. 写入 slaughter_inspection 表
        ├── 3. 调用 file-service 计算文件 SHA-256
        ├── 4. 组装存证数据：content_hash + vet_e_signature + timestamp
        │
        ▼
  发送消息到 RabbitMQ ────→  blockchain-service 消费
  (异步，不阻塞用户)              │
                                  ├── 5. 调用智能合约 storeSlaughterInspect()
                                  ├── 6. 等待交易确认（获取 tx_hash + block_number）
                                  ├── 7. 写入 blockchain_record 表
                                  └── 8. (失败时) 重试3次 → 写入死信队列 → 人工补录
```

### 7.3 批次拆分树状结构示例

```
                    胴体批次 CB20240710001
                    (生猪 ID: 1,2,3)
                   /          |          \
                  /           |           \
         二分体_L        二分体_R       二分体_F
   SP2024071000101  SP2024071000102  SP2024071000103
      /       \           |               |
     /         \          |               |
  前腿肉      后腿肉    五花肉          排骨
  SP...011   SP...012  SP...013       SP...014
  (5kg×4包)  (6kg×3包)  (3kg×5包)    (2kg×8包)
```

链上存储时，每个子批次 `SP*` 都记录其 `parentBatchNo`，形成不可篡改的树状溯源路径。

### 7.4 应急追溯 — 秒级反查流程

```
输入问题批次号 "SP20240710001011"
        │
        ▼
  trace-service.search("SP20240710001011")
        │
        ├── 上游追溯（递归查询 parent_batch_no）:
        │   SP...011 → SP...0101 → CB...001 → pig_id[1,2,3]
        │                            → 查出养殖场、疫苗、检疫证、屠宰场
        │
        ├── 下游追溯（查询所有 parent_batch_no = 当前批次的记录）:
        │   SP...011 → 冷链运输 → 门店签收 → 零售终端
        │
        └── 返回完整链路，含每条记录的区块链存证状态
```

## 八、安全性设计

| 维度 | 措施 |
|------|------|
| 身份认证 | JWT Token + 刷新Token机制；Token有效期2小时 |
| 权限控制 | RBAC模型，按角色（养殖/屠宰/配送/零售/监管/管理员）控制菜单、按钮、API |
| 数据签名 | 机构CA证书 + SM2数字签名，关键操作需电子签章 |
| 数据完整性 | 所有上链数据计算SHA-256，消费者可一键对比链上哈希 |
| 防篡改 | 修改存证数据不会覆盖链上记录，而是追加新版本并留痕 |
| 文件安全 | 上传文件类型白名单、大小限制（图片≤10MB，视频≤50MB）、病毒扫描 |
| 防重放 | 每次写链操作带 nonce，合约校验去重 |
| 国密合规 | 哈希算法 SM3，签名算法 SM2，满足国内监管要求 |

## 十、关键技术难点与解决方案

| 难点 | 解决方案 |
|------|----------|
| 双链适配（FISCO BCOS / Fabric） | blockchain-service 内部使用**适配器模式**，定义统一 `BlockchainAdapter` 接口，分别实现 `FiscoBcosAdapter` 和 `FabricAdapter`，通过配置切换 |
| 大模型生成模拟轨迹 | 调用 LLM API，Prompt 模板："生成从{养殖场}到{屠宰场}再到{门店}的冷链物流轨迹，包含温度波动（-5℃~0℃），时间跨度48小时，输出JSON" → 批量写入 temperature_log 表 |
| 批次拆分树状结构递归查询 | MySQL 8.0 支持 CTE（Common Table Expression）递归查询，`WITH RECURSIVE split_tree AS (...)` |
| 区块链交易延迟 | 采用**异步上链**：业务操作不等待链确认，通过 RabbitMQ 异步投递；前端展示"待确认-已上链"两种状态；可手动重试 |
| 文件哈希与链上一致性 | file-service 在上传时即时计算 SHA-256，返回给调用方；上链时直接使用该哈希，不二次计算，避免不一致 |
| Demo 阶段数据初始化 | 编写 `DataInitRunner`，在应用启动时检测 `spring.profiles.active=demo`，自动插入模拟养殖场、生猪、疫苗、屠宰、分割、运输、门店数据 + 批量调用 LLM 生成物流轨迹 |
