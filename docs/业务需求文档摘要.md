## 一、通用技术栈实现规范

| 类别 | 技术选型与实现说明 |
|------|------------------|
| 区块链底层 | 支持双链架构：FISCO BCOS 或 Hyperledger Fabric，采用Docker单机部署4节点模式，满足演示与测试环境需求 |
| 后端服务 | 使用Spring Boot构建微服务架构，集成MySQL作为主关系型数据库，Mybatis实现ORM映射 |
| 前端展示 | Web管理端基于Vue3开发，支持复杂表单与数据看板；消费者端采用Uni-app框架开发微信小程序，实现跨平台兼容 |
| 数据上链策略 | 仅将“关键状态变更”的哈希值及“质检报告摘要”上链；原始图片、视频文件存储于本地文件系统，链上仅保存其SHA-256指纹 |
| 物流轨迹处理 | 不依赖GPS实时追踪，改为“关键节点手动打卡或扫码录入”方式记录物流进展；在Demo阶段，利用大模型批量生成符合实际逻辑的模拟轨迹数据用于展示 |

## 六、数据流与业务流程分析

### 全链路数据流转逻辑

1. **数据采集层**
   - 生产端通过Web管理端录入关键事件数据（如投苗、捕捞、检疫等）
   - 支持拍照上传原始凭证（检测报告、温度快照、证照等）
   - 关键物流节点通过手动打卡或扫码方式录入时间与位置

2. **数据处理与存储分工**
   - 原始多媒体文件（图片、视频、PDF）统一存储于本地文件系统
   - 提取文件SHA-256指纹，结合业务数据生成摘要信息
   - 将“关键状态变更哈希”与“质检报告摘要”写入区块链，实现不可篡改存证

3. **消费者验证流程**
   - 消费者通过微信小程序扫描产品二维码
   - 页面加载本地数据库中的详细溯源信息
   - 触发“一键验真”功能，自动获取链上对应哈希值
   - 对比页面数据生成的哈希与链上存储哈希是否一致，显示“✅ 区块链已验证”

4. **监管与应急响应**
   - 监管部门可通过监管审计模块查看认证信息与审计日志
   - 发生质量问题时，通过“应急追溯”模块输入批次号，系统秒级定位所有关联上下游节点
   - 召回指令一经发布即上链，确保责任可追溯、通知不可抵赖
