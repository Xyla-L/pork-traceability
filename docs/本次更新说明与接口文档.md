# 本次更新：AI 自然语言操作 · 前端接入说明

> **这次上线了什么**：web-admin 的 AI 助手多了一个「操作」模式。
> 用户在对话框里说一句中文（「查看 pigId 为 1 的产地检疫证明」），系统自己找到对应接口、
> 缺参数就追问、确认后带着当前登录用户的身份真实执行，把结果结构化返回给前端渲染。
>
> **本文只讲前端要接什么、要画什么。** 后端怎么建图、怎么打分、五道安全闸怎么开的，
> 在 [`知识图谱与自然语言操作.md`](./知识图谱与自然语言操作.md) 里，前端同学不用看。

- 前端改动：`web-admin/src/api/modules/ai.ts`、`components/ai/AiChatDrawer.vue`、`components/ai/ActionBubble.vue`（均已提交，可直接复用）
- 后端模块：`backend/ai-service`
- 图谱规模：39 模块 / 218 接口 / 10 服务（其中 53 个服务间接口、112 个只读接口）

## 一、这次上线了什么功能

### 1.1 用户视角：一次完整交互

用户在 AI 助手里切到「操作」模式，输入：

```
查看 PigID 为 1 的产地检疫证明
```

前端拿到一张卡片，从上到下是：

```
┌────────────────────────────────────────────────────────┐
│ [已执行]  查看产地检疫证明   GET  /pigs/{pigId}/quarantine-cert │
│ 已执行「查看产地检疫证明」。共 1 条。                      │
│ ┌ 执行成功 ─────────────── HTTP 200 · 87 ms ─────────┐ │
│ │ {                                                   │ │
│ │   "code": 200,                                      │ │
│ │   "data": { "pigId": 1, "certNo": "JY20261101001" }  │ │
│ │ }                                                   │ │
│ └─────────────────────────────────────────────────────┘ │
│ 参考：另外 2 个近似接口 ▾                                │
└────────────────────────────────────────────────────────┘
```

如果用户只说「查看产地检疫证明」没说哪头猪，卡片会变成：

```
┌────────────────────────────────────────────────────────┐
│ [需要补充信息]  查看产地检疫证明   GET  /pigs/{pigId}/quarantine-cert │
│ 要查看产地检疫证明，还需要补充：pigId（数字）。             │
│ 还需要  [pigId（数字）]                                  │
└────────────────────────────────────────────────────────┘
```

用户直接在输入框补一句「1」，前端带着上一轮的 `conversationId` 再发一次，
系统就知道是在给 `pigId` 填值，参数齐了立刻执行。

### 1.2 能力边界（决定了 UI 该怎么提示）

| 场景 | 后端行为 | 前端实际会看到 |
|---|---|---|
| 查询类（GET） | 参数齐了**直接执行**，不用点确认 | 一次请求直接拿到结果 |
| 改数据类（POST/PUT/DELETE） | **默认从候选里剔掉**，不执行。只有管理员在配置里点名放开过的接口，才会走到「等你确认」 | 多半是「没找到对应功能」，或者落到一个语义相近的只读接口（回答前会带「按关键词匹配选的」提示） |
| 服务间内部接口、认证服务 | 一律不执行，也不会进候选 | 同上，用户无感知 |
| 说的话对不上任何接口 | 返回 `UNSUPPORTED` | 展示提示，引导换说法 |

> 一句话给用户解释：**现在能问、能查，但还不能替你改数据。**
> 不要让用户以为「点了就能审批/删除」，否则投诉会比较多。
> 另外前端**不要**写死「需要管理员开启」这类文案——那是检索调试接口里的
> `denyReason`，对话接口不会直接吐给用户。

### 1.3 已实测能听懂的说法（拿来当测试用例）

| 用户说法 | 检索命中的接口 | 说明 |
|---|---|---|
| 查询批次 P20261101 的检疫证明 | `GET /pigs/{pigId}/quarantine-cert` | 0.88 分，会追问 pigId |
| 查一下这个月各养殖场的存栏量 | `GET /farms/page` | 0.85 分 |
| 看看有哪些过期的产品 | `GET /sales/warnings` | 0.67 分 |
| 把上个月张三负责的退货单导出来 | `GET /distribution/return-pool` | 0.64 分（项目里没有导出接口，给近似结果） |
| 今天卖了多少猪肉 | `POST /sales/records` | 0.58 分。写接口被过滤，对话里会落到 `GET /sales/records` 并提示「按关键词匹配选的」 |
| 把这条召回单标记为已完成 | `PUT /sales/recalls/{id}/status` | 0.58 分。同上，只能给出近似查询，不会真的改状态 |

> 上表是**检索层**（`/ai/graph/search`）的结果。对话层会再过一遍执行策略，
> 所以写操作那两行在前端看到的效果会是「近似查询」而不是「执行成功」。

## 二、前端要接的接口

### 2.1 清单

| 优先级 | 方法 | 网关路径 | 用途 |
|---|---|---|---|
| **必接** | POST | `/api/v1/ai/action/chat` | 发一句话，拿到结构化结果（多轮补参数都走这里） |
| **必接** | POST | `/api/v1/ai/action/confirm` | 用户点「确认执行」时调 |
| 可选 | GET | `/api/v1/ai/graph/search?q=&topK=` | 检索调试：看一句话会被理解成哪几个接口、为什么没执行 |
| 可选 | GET | `/api/v1/ai/graph/stats` | 图谱规模，排障时看「是不是图谱没加载」 |
| 不用接 | POST | `/api/v1/ai/admin/graph/rebuild` | 管理员重建图谱，走管理端页面或用 curl |

鉴权：和现有接口一样带 JWT 即可（`Authorization: Bearer xxx`），网关会解析出用户身份。
**前端不要自己塞 `X-User-Id`**，那是网关的活。

### 2.2 响应外壳与错误码

所有接口都包一层 `Result<T>`：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { },
  "traceId": "2db0825d12a94aa29e0ffc5b1480e144",
  "timestamp": 1795072711949
}
```

| code | 含义 | 前端怎么处理 |
|---|---|---|
| 200 | 请求处理完了。**业务失败也是 200**，看 `data.phase` | 正常渲染卡片 |
| 400 | 缺参数（`q` 或 `conversationId`） | 属于前端 bug，控制台报错即可 |
| 401 | 未登录 / token 过期 | 走现有登录跳转逻辑 |
| 403 | 调了 `/ai/admin/**` 但角色不是 SUPERVISOR/ADMIN | 提示无权限 |
| 503 | 该功能被后端配置关掉了 | 提示「该功能暂未开放」 |

> **为什么业务失败不用非 200**：一次操作的结果分三段——「理解成了什么」「还缺什么」
> 「执行成功没有」，其中「还缺什么」是正常流程不是错误。用 `phase` 表达比堆 HTTP 码清楚。
> 所以前端**不要**用 `response.ok` 判断成没成功，要根据 `phase` 判断。

## 三、核心：`phase` 五种状态怎么画

这是前端**唯一需要记住的东西**。后端所有返回都归到这五态，UI 按 `phase` 分支即可。

### 3.1 状态表

| phase | 含义 | 标签文案（组件已实现） | 卡片内容 | 要不要按钮 |
|---|---|---|---|---|
| `UNSUPPORTED` | 没找到对应功能 | 没找到对应功能（灰 `info`） | 纯文本提示 `question` | 无 |
| `NEED_SLOT` | 接口选对了，缺必填参数 | 需要补充信息（黄 `warning`） | 提示语 + 缺失参数标签 + 已填参数 | 无（用户直接在输入框补） |
| `READY` | 写操作，参数齐了，等确认 | 等待确认（黄 `warning`） | 提示语 + 「确认执行」按钮 | **要**，点了调 `/action/confirm` |
| `EXECUTED` | 执行成功 | 已执行（绿 `success`） | 结果面板：成功图标 + HTTP 码 + 耗时 + 返回数据 | 无 |
| `FAILED` | 两种可能：① 执行了但失败（`execution` 不为 null，下游报错/连不上）② 压根没执行（会话过期、参数超长、功能未开，`execution` 为 null） | 执行失败（红 `danger`） | 有 `execution` 就画失败面板（红叉 + `execution.error`），没有就纯文本提示 `question` | 无 |

### 3.2 两条链路

**查询类（读操作）—— 直接执行**

```
用户输入
  └→ POST /action/chat ──→ NEED_SLOT（缺参数）
        │                    └→ 用户补充 ──→ POST /action/chat（带 conversationId）──→ EXECUTED
        └──────────────────→ EXECUTED（参数已齐，一次到位）
```

**改数据类（写操作）—— 必须确认**

```
用户输入
  └→ POST /action/chat ──→ READY（参数齐，等你确认）
        └→ 用户点「确认执行」──→ POST /action/confirm（只传 conversationId）──→ EXECUTED / FAILED
```

注意两点：

1. **补参数不调 `confirm`，还是调 `chat`**。用户补的是一句话（「1」），
   不是表单值，仍然要过一遍理解。
2. **`confirm` 不传参数**。参数留在服务端会话里，前端只回传 `conversationId`。
   这样前端无法绕过参数校验，别想着「我拼个完整 body 一次执行掉」。

### 3.3 现成组件

`components/ai/ActionBubble.vue` 已经按这五态画好了：phase 标签、接口摘要 + method 徽章、
缺失参数标签、已填参数、执行结果面板（>600 字折叠）、确认按钮、候选折叠。
直接喂 `ActionChatResult` 即可：

```vue
<ActionBubble :result="msg.action" :confirming="msg.confirming" @confirm="confirmAction(i)" />
```

## 四、POST `/api/v1/ai/action/chat`

### 4.1 请求体

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `text` | string | 是 | 用户这句话，**上限 500 字**，超了返回 `FAILED` |
| `conversationId` | string | 否 | 上一轮返回的值。**空字符串或 null 都表示新会话**，前端直接传 `''` 即可 |
| `reset` | boolean | 否 | `true` 丢掉上下文重开（用户说「算了换个事」） |

> ⚠️ **字段名是 `text`，不是 `message`。** 写错了 Jackson 会静默忽略，
> 接口返回「请输入你想做的事」，看起来像检索失败。这个坑已经踩过一次。

```js
// 前端现成封装（api/modules/ai.ts）
aiApi.actionChat(text, conversationId)   // → ActionChatResult
```

```bash
curl -X POST 'http://localhost:8089/ai/action/chat' \
  -H 'Authorization: Bearer <用户JWT>' -H 'Content-Type: application/json' \
  -d '{"text":"查看产地检疫证明","conversationId":""}'
```

### 4.2 响应 `data` 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `phase` | string | 五态之一，见第三节 |
| `conversationId` | string | **每轮都要存下来**，下一轮带上 |
| `operation` | object \| null | 选中的接口。`UNSUPPORTED` 时为 `null` |
| `operation.id` | string | 接口唯一标识，形如 `op:breeding-service:GET:/pigs/{pigId}/quarantine-cert` |
| `operation.summary` | string | 中文摘要（「查看产地检疫证明」），卡片主标题就用它 |
| `operation.method` / `.path` | string | HTTP 方法、服务内路径，用来画徽章 |
| `operation.gatewayPath` | string | 拼好网关前缀的完整路径，展示用，不用来发请求 |
| `operation.module` / `.service` | string | 所属模块 / 服务名 |
| `slots` | object | 已收集的参数。**执行完成后是空对象**（`EXECUTED` 时别指望拿到入参） |
| `missing` | array | 还缺的必填参数，`[{name, type, hint}]`，`hint` 是给用户看的（如「数字」） |
| `question` | string | 要展示给用户的那句话（追问或提示） |
| `answer` | string | 最终答复，**后端模板生成，不含模型幻觉** |
| `execution` | object \| null | 执行结果，没执行时为 `null` |
| `execution.success` | boolean | 业务是否成功（后端已兼顾 HTTP 200 + `{"code":500}` 两种情况） |
| `execution.status` | int | 下游 HTTP 状态码，`-1` 表示请求根本没发出去 |
| `execution.elapsedMs` | long | 耗时（毫秒） |
| `execution.data` | string \| null | 下游原始响应，**是 JSON 字符串不是对象**，要自己 `JSON.parse` |
| `execution.error` | string \| null | 失败原因，已脱敏（内网地址会被抹成「内网服务」）、截断 200 字 |
| `candidates` | array | 本次检索候选 `{id, summary, method, score}`，做「另外 N 个近似接口」折叠用 |

`question` 和 `answer` 内容基本一致（一个表述为「要对用户说的话」，一个是「最终答复」）。
**只渲染其中一个**，两个都画会重复。现有 `ActionBubble` 用的是 `question`。

### 4.4 示例：执行完成

```json
{
  "code": 200,
  "data": {
    "phase": "EXECUTED",
    "conversationId": "d1f38717-7bd7-4b2f-b1e0-65a704dc2422",
    "operation": {
      "id": "op:breeding-service:GET:/pigs/{pigId}/quarantine-cert",
      "summary": "查看产地检疫证明",
      "method": "GET",
      "path": "/pigs/{pigId}/quarantine-cert",
      "gatewayPath": "/api/v1/breeding/pigs/{pigId}/quarantine-cert",
      "module": "产地检疫证明管理",
      "service": "breeding-service"
    },
    "slots": {},
    "missing": [],
    "question": "已执行「查看产地检疫证明」。共 1 条。",
    "answer": "已执行「查看产地检疫证明」。共 1 条。",
    "execution": {
      "success": true,
      "status": 200,
      "elapsedMs": 87,
      "data": "{\n  \"code\": 200,\n  \"data\": { \"pigId\": 1, \"certNo\": \"JY20261101001\" }\n}",
      "error": null
    },
    "candidates": []
  }
}
```

两个容易被误会的地方：

- `slots` 是空对象，**不是前端传错了**。执行成功后后端会清空参数，
  否则用户连着问两次同一件事，第二次会直接用上一次的参数。
- `answer` 末尾的「共 1 条」是后端按响应结构自动补的（数组 → `共 N 条`，
  分页 → `共 total 条，本页返回 M 条`），不是模型编的。前端**不要再二次加工**。

```json
{

  "operation": { "id": "op:breeding-service:POST:/farms", "summary": "创建养殖场", "method": "POST", "...": "..." },
  "slots": { "farmName": "示范猪场" },
  "missing": [],
  "question": "即将执行「创建养殖场」（POST /farms），确认继续吗？",
  "answer": "即将执行「创建养殖场」（POST /farms），确认继续吗？"
}
```

## 五、POST `/api/v1/ai/action/confirm`

### 5.1 请求体

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `conversationId` | string | 是 | 上一步 `READY` 返回的那个值，**不能为空** |

```js
aiApi.actionConfirm(conversationId)   // → ActionChatResult，结构和 chat 完全一样
```

```bash
curl -X POST 'http://localhost:8089/ai/action/confirm' \
  -H 'Authorization: Bearer <用户JWT>' -H 'Content-Type: application/json' \
  -d '{"conversationId":"d1f38717-7bd7-4b2f-b1e0-65a704dc2422"}'
```

响应与 `/action/chat` **同一个结构**，`phase` 通常是 `EXECUTED` 或 `FAILED`，
偶尔 `NEED_SLOT`（等待确认期间参数被清掉了，退回去重问）。

### 5.2 会话失效

会话默认 **10 分钟**过期；同一个会话**确认执行过一次后就不能再确认**（要重新发起）。
失效时返回：

```json
{
  "code": 200,
  "data": {
    "phase": "FAILED",
    "conversationId": "xxx",
    "operation": null,
    "slots": {},
    "missing": [],
    "question": "会话已过期，请重新描述一次要做什么。",
    "answer": "会话已过期，请重新描述一次要做什么。",
    "execution": null,
    "candidates": []
  }
}
```

可能的提示文案有三种（`question` 与 `answer` 内容相同），前端都当普通文本渲染即可，不用分情况：

- `会话已过期，请重新描述一次要做什么。`
- `当前没有等待确认的操作。`（重复点了确认按钮）
- `选中的接口已经不在图谱里了，请重新发起。`（后端重建过图谱）

**按钮要防重复点击**：点一次就置 loading，`confirm` 返回后禁用。

## 六、GET `/api/v1/ai/graph/search`（可选，调试用）

不执行任何东西，纯检索，可以放心刷。做「为什么没找到」排查面板时用。

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `q` | string | 必填 | 自然语言。**用 `encodeURIComponent` 编码**，中文直接拼进 URL 会编码错乱导致搜不到 |
| `topK` | int | 8 | 返回条数，后端夹在 1~20 |

```js
aiApi.graphSearch('查看产地检疫证明', 3)
```

响应 `data`：

| 字段 | 说明 |
|---|---|
| `query` | 原始查询 |
| `count` | 返回条数 |
| `items[].id` / `.method` / `.path` / `.gatewayPath` / `.summary` | 接口信息 |
| `items[].score` | 0~1 相关度，越高越匹配 |
| `items[].hits` | 命中的词，排障时最有用（能看出是「检疫」还是「证明」带来的命中） |
| `items[].executable` | **后端真实执行策略的结论**，不是猜的 |
| `items[].denyReason` | 不能执行时的原因，能执行时**这个字段不存在**（注意判空） |

```json
{
  "data": {
    "query": "查看产地检疫证明",
    "count": 2,
    "items": [
      {
```

## 九、联调注意事项（都是踩过的）

1. **请求字段是 `text` 不是 `message`**。写错不报错，只会返回「请输入你想做的事」。
2. **`/action/*` 用普通 JSON，不要走 SSE**。问答模式那条链路才是流式，
   这两个接口返回的是结构化结果，硬套流式没意义。header 用 `Content-Type: application/json`。
3. **`conversationId` 每轮都要更新**，从响应的 `data.conversationId` 取，
   不要自己生成 UUID（后端认不出）。
4. **`execution.data` 是字符串**，展示前 `JSON.parse`，解析失败就直接当文本显示（下游可能返回纯文本）。
5. **`slots` 执行完是空的**，别拿它当「刚才传了什么」的依据；要看入参请记录自己的输入。
6. **`candidates` 可能少于 2 条甚至为 0**，折叠区判空再渲染（`candidates.length > 1` 才显示）。
7. **降级时 `question` 前面会多一段话**，原文是：
   `（当前连不上大模型，这是按关键词匹配选出来的接口，可能不是你想要的；换个说法或说得更具体些可以提准。）`
   这是后端连不上千问时的兜底提示，属于正常现象，前端原样展示即可，**不要截断或过滤**。
8. **`denyReason` 字段可能不存在**（能执行时后端不返回），判空写 `item.denyReason ?? ''`。
9. **500 字上限**。超了返回 `FAILED` + 「这句话太长了」，建议输入框就限制 `maxlength=500`。
