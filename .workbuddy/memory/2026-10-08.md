## 申请出栏接入称重设备通道 + 全链路审批落实名（用户拍板：「要」）

### 先摆清的性质差异（回答用户「称重设备自动申请出栏 + 审批用登录用户名实名可以吗」）
- **申请出栏 = 设备能采一半**：设备给得出「哪头猪、多重、何时、哪台设备」；给不出「目标屠宰场」——那是**去向声明**不是测量值。故策略定 `DEVICE_PREFERRED`（设备优先），缺去向转人工补录。

- 现象：首次跑验证，「审批通过」是成功的，但库里 `slaughter_apply.approver` = `3F3F3F3F3F`（**五个问号**，不是终端显示问题，用 `HEX()` 确认）。`source_ref` 同样。

- **教训**：任何「把中文字符串塞进 HTTP 头」的透传设计都要先编码；以前没暴露只是因为透传的是 ASCII 账号名。判断是否真乱码要用 `HEX()`，光看 `-t` 输出会把 `?????` 当成终端编码问题。

**业务口径（回答用户「瘦肉精实际是按批测还是逐头测」）**：屠宰环节的瘦肉精检测是**批批检 + 按批抽检**，不是逐头检。抽检阳性 → **整批受控**：同批猪一律不得屠宰放行、产品不得出厂，阳性样本隔离处理并按规定上报、追溯来源养殖场。所以系统口径是「一批阳性整批停」，不是「一头阳性一头停」。

1. `SlaughterDeviceIngestService.ingestInspection`（屠宰检验）——判定放在**幂等查找之前**，阳性后设备重推要拿到「被拒绝」而不是「返回既有记录」。
2. `SlaughterDeviceIngestService.ingestStamp`（胴体盖章）——放在「已有合格检验」之前，好给出「因为阳性」而不是「因为没有合格检验」这个更准确的原因。

## 瘦肉精「未检不得屠宰」落地（用户回「要」，接上一轮抛出的待定口径）

上一轮留了一个口子：一头从头到尾没做过瘦肉精检测的猪，仍能进屠宰检验 / 盖章 / 建胴体批次。本轮补齐。

### 口径（与「一批阳性整批停」同一套粒度）
- **已检 = 该猪自身有「出了结果」的检测记录，或它所属批次有「出了结果」的检测记录**（按批抽检，代表样本覆盖整批）。两者都查不到就是「未检」→ 确定性拒绝（`retryable=false`），force 也不放行。
- **「所属批次」取三个来源的并集**：本次上报文的 `batchNo` + 该猪的**入场查验批次** + 它自己检测记录上的 `batchNo`。原因：设备这次可能填了个不相干的批次号，不能因此绕过「它真正归属的那一批里有阳性」这件事——单头判断里也顺带把批次阳性检查扩成了这并集（原来只查上报批次）。
- **「待检测/检测中」不算已检**：只有 `result` 非空（出了结论）的记录才是放行凭证。

## 屠宰检验：补「未做宰前检查不得屠宰」门槛 + 把「同步检验」按法规口径摆正（用户回「都做」）

### 先答的业务问题（已核实现行规程，别再凭印象答）
- **同步检验是什么**：《动物检疫管理办法》第二十条「动物屠宰过程实行全流程同步检疫」；《生猪屠宰检疫规程》的操作程序是 入场监督查验 → 检疫申报（屠宰前 6h）→ 宰前检查（屠宰前 2h 内）→ 同步检疫 → 结果处理。**规程里根本没有单独的「宰后检疫」一节——宰后检疫的标准做法就是同步检疫**。所以系统把 2=宰后、3=同步 做成两种独立类型，按法规口径是错的，它俩是同一环节。
- **一定要做宰前检验吗**：要，且不是「做了就行」，是「**合格才能屠**」（第二条引用同一条：屠宰前应当逐头临床检查，健康的动物方可屠宰）。实务上这是硬门槛，跳过它后面出的检疫证明站不住。

### 核心设计口径
- **批次边界由系统算，设备只报「单头白条」的事实**；设备报文**不带批次号**（「哪几头算一批」是业务归集决策，交给称重台会造跨场混批/一猪两批）。
- **归集键 = 屠宰场 + 屠宰日**（`lineNo`/班次留作后续细分，本轮不做）；命中当日同场 `DEVICE` 批次则追加 `pig_ids` + 累加重量，未命中新建（`CB` 前缀）。**不设「封批」**：当天最后一头落完，次日自然开新批。
- **三道硬校验，顺序有意为之**：瘦肉精（判批）→ 胴体盖章（判头）→ 未被占用。设备重推命中第三道时**回既有批次（`written`）而不是报错**。
- **来源策略 `DEVICE_PREFERRED`**（不是 `DEVICE_ONLY`）：并非所有屠宰场均装分拣台，无设备的场仍需人工建批，但要先取兜底解锁票据。
- **设备归集只在 `DEVICE` 批次之间做**，不去动人工批次；**设备批次只开放备注**（关联猪/重量/屠宰场是过磅归出来的结果）。
- **归集批次操作人留空**（机器行为，按「设备 ≠ 人」不拿设备名顶）；`source_ref` = 分拣台编号。
