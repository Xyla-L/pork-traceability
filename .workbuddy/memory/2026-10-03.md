## 来源管控（关键环节只认设备）—— 设计与落地

**背景**：用户提出"能不能删掉所有人工录入来保住区块链数据不被篡改"。
结论是不能：链上只保证"上链后改不了"，管不了"上链前谁写的"；
删人工只是把造假成本从"填表单"抬到"偷密钥"，还会让异常数据的待人工队列永远卡死。
用户采纳的方案是：**关键环节强制设备来源 + 人工只能实名复核 + 全程留痕**。

### 策略模型（代码内置，不放数据库，避免多服务口径漂移）

- `common-core` 新增包 `com.pork.core.source`：
  - `SourcePolicy`：DEVICE_ONLY（设备独占，人工新增直接拒）/ DEVICE_PREFERRED / MANUAL_ALLOWED
  - `TraceStage`：11 个环节 ↔ 设备通道 ↔ 目标表 ↔ 策略，**唯一真相源**
  - `SourcePolicyRegistry`：策略解析，含应急覆盖；**无设备通道的环节自动退化为 MANUAL_ALLOWED**（否则锁死业务）
  - `ManualOperator`：operatorId（X-User-Id=用户ID）/ operatorName（X-User-Name=登录用户名）
- `common-web` 新增 `SourceGuard`（校验闸门 + 取操作人 + 策略视图）+ `SourcePolicyProperties`
  （`pork.trace.source.enforce-device-only` / `overrides`，配置写错不阻断启动）

**环节归属**：设备独占 = 入场查验 / 瘦肉精 / 屠宰检验 / 胴体盖章；
设备优先 = 产地检疫(无通道) / 养殖建档 / 免疫注射 / 分割批次；人工可录 = 温度 / 签收 / 零售。

### 三道防线

1. 前端 `SourceGuardBar.vue` 按 `GET /ingest/source-policy` 决定是否渲染新增按钮（表现层，不承担安全职责）
2. 业务服务人工新增方法首行 `sourceGuard.requireManualAllowed(TraceStage.X)` → `BusinessException(FORBIDDEN=2003)`；
   并把 `source/sourceRef/rawPayload` 从 DTO copy 中排除，**人工无法伪装成设备**
3. 接入层 `approve` 对关键环节强制实名 + 必填放行理由，与原始报文一起留档

### 上链增强

- 人工写入也带 `source=MANUAL` + `operator` 进 payload
- 设备来源记录被人工编辑时补发 `*_MANUAL_EDIT` 事件（独立 bizKey，不影响原哈希验真）
- 作废事件带 operator

### 关键踩坑

- **`@Valid` 先于业务方法执行**：验收脚本最初提交的不完整报文被参数校验挡下（code=1001），
  证明不了管控闸门存在。检测类用例必须给"字段齐全、能过校验"的报文，才能看到 2003。
- **JWT subject 是用户ID不是用户名**：`X-User-Id` 被 trace-service 的举报接口按 `Long` 解析，
  不能改语义。做法是在令牌里新增 `userName` 声明，网关注入 `X-User-Name`，
  业务表 source_ref 记用户名、接入层 handler 记「用户名(用户ID)」。
  改 `JwtUtil` 私有 `generateToken` 签名时漏改两个 4 参调用点，导致 compose build 失败一次。
- 入场查验用例最初 5000：`healthCheck` 传了中文字符串（DTO 是 Integer），Jackson 反序列化失败。

## 来源管控升级：兜底解锁 + 作废同级受控 + 追溯标注（更合理的版本）

**用户的四条最终要求**：① 设备为默认通道，人工降级为「兜底入口」——默认隐藏、需申请解锁，
录入强制实名+理由+标 MANUAL；② 结论类字段禁止原地改，只允许「作废+重录」；
③ 作废/更正与新增同级别受控，防止「用作废绕开管控」；④ 追溯查询统一「取当前有效记录」，
作废记录保留标注不物理删。

### 1. 兜底解锁通行证（人工口子的可控化）

- 新增 `common-core` `com.pork.core.source.FallbackTicket` + `common-web` `FallbackTicketCodec`
  —— **无状态 HMAC-SHA256 签名票据**，格式 `v1|环节|失效时间戳|申请人ID|申请人姓名|签名`。
- 为什么不用跨服务回调/存库校验：兜底发生在**设备异常或断网**时，此时去校验中心服务大概率也不通；
  签名票据本地可验、零依赖。代价是**无法即时吊销**——这一点如实写进了文档和前端文案，
  补偿手段是「短时效（默认 120 分钟，上限 24 小时）+ 每次使用打 `source_fallback_used` 日志 + 数据标 MANUAL 并上链」。
- `SourceGuard`：`requireManualAllowed` 在 DEVICE_PREFERRED 环节要求请求头 `X-Fallback-Ticket`
  且票据环节必须与目标环节一致（防 A 环节的票去写 B 环节）。
- `ingest-service` 新增 `FallbackUnlockService` + `source_fallback_unlock` 表（申请/关闭/查询），
  申请需实名+理由，`close` 只收回申请记录并清本机票据（文档已注明不能吊销已签发票）。
- 前端：`web-admin/src/utils/fallbackTicket.ts`（localStorage 存票 + axios 请求拦截器按路由自动附加），
  设备接入页新增「兜底解锁」页签（申请 / 列表 / 关闭）。

### 2. 编辑与作废：把「偷偷改」变成「只能公开推翻」

- **字段分两类**：结论字段（批号、结果、编号、签章等）禁改，改则 `SourceGuard.rejectConclusionChange`
  抛 `【结论保护】`；说明性字段允许改并留痕。
  `SourceGuard.sameValue()` 用 `BigDecimal.compareTo` 数值比较，避免 `1` vs `1.0` 被误判为改动。
- **作废与新增同级受控**：新增 `SourceGuard.requireVoidAllowed(stage, reason)`
  —— 实名（未登录直接拒）+ 理由≥2 字 + DEVICE_PREFERRED 环节要票据；
  DEVICE_ONLY 环节允许作废但打 WARN（录错的数据连作废都不许只会在库里越积越脏）。
  改造了 8 处作废方法（屠宰 4 + 养殖 3 + 分销 1）。
- **作废四列统一**：`void_flag / void_reason / void_operator / void_time`。
  `void_flag` 同时作为 MyBatis-Plus `@TableLogic` 逻辑删除标记（`logic-delete-value: 1`），
  于是**所有常规查询自动只见有效记录**——这是要求④「取当前有效记录」的实现基础。

### 3. 追溯侧的「作废标注」（要求④的难点）

`@TableLogic` 会滤掉作废行（这是对的），但追溯必须能说明「这一环原本有记录、后来被作废了」。
解法：**在追溯标注路径用显式绕过逻辑删除的只读 `@Select`**，绝不参与任何写路径。

- 屠宰 4 个 Mapper 加 `selectVoidedByPig`；养殖 `PigIndividualMapper` 加 `selectVoidedById` /
  `selectVoidedByEarTag`；`VaccineRecordMapper` / `QuarantineCertMapper` 加 `selectVoidedByPig`。
- `BreedingInternalController.byEarTag`：档案不存在时查作废表，命中则明确回报
  「该耳标对应的生猪档案已被作废…作废理由：xxx」，而不是含糊的「不存在」。
- `SlaughterInternalController.traceByPigs` 每行补 `voided` 数组（环节/单号/理由/操作人/时间）。
- `TraceQueryServiceImpl.full(batchNo)` 汇总 breeding + slaughter 的作废明细 →
  `voidedRecords` + `voidedSummary`（中文说明句）。
- 前端 `TraceSearch.vue` 增作废警示条，逐条列出「已作废」标签 + 环节 + 单号 + 理由 + 操作人/时间。

## 设备独占终态：采集类人工新增端点整条删除

**背景**：用户进一步明确「把数据采集类都只留自动化录入，删除人工录入功能」。
与此前"兜底解锁 + 人工留痕"不同，这次是把 8 个有设备通道的采集环节的人工新增入口**从代码里删掉**。

### 策略变更（TraceStage）

- `TAG` / `VACCINE` / `SPLIT`：DEVICE_PREFERRED → **DEVICE_ONLY**（人工入口删除）
- `TEMPERATURE`：MANUAL_ALLOWED → **DEVICE_ONLY**（人工补录入口删除）
- `QUARANTINE`（产地检疫出证）：**唯一保留的人工采集口**（无设备通道，删了检疫证就永远出不了，
  入场查验核验证件整条链断掉），仍须实名 + 兜底解锁
- `RECEIPT` / `SALE`：人工可录（"人做业务"不是"数据采集"）

### 删除的后端端点（8 个 @PostMapping + 对应 Service 方法/接口声明）

`POST /slaughter/entries`、`/slaughter/ractopamine`、`/slaughter/inspections`、`/slaughter/stamps`、
`/breeding/pigs`、`/breeding/pigs/{id}/vaccines`、`/distribution/splits`、`/distribution/transports/{id}/temperature`。
设备通道走独立的 `*/internal/ingest/*` 内部端点，与人工入口无共用路径，删除互不影响。
同路径只剩 GET，所以 POST 撞 405——比"进业务代码再抛异常"更干净。

### 关键教训：Maven 增量编译的假 SUCCESS

第一次 `mvn compile` 报 BUILD SUCCESS，但日志里全是 `Nothing to compile - all classes are up to date`
——TraceStage 里 `TEMPERATURE` 误以 `;` 结尾导致 `RECEIPT`/`SALE` 脱离常量列表（语法错误），
却因增量判定跳过而没被发现。**改公共模块后必须 `mvn clean compile`，并 grep 确认 0 个 "Nothing to compile"**。
修复语法后全量重编 BUILD SUCCESS、0 ERROR。
