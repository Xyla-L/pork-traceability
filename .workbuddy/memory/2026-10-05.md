**踩到的两个坑（重要，下次别再踩）**

1. **`ingest_staging.payload` 是 MySQL 的 `json` 类型**：`payload = ?` 拿字符串参数比**永远不相等**（JSON 列与字符串不走文本相等，且 MySQL 会把 JSON 输出的键序/空格重排）。必须用 `.apply("payload = CAST({0} AS JSON)", rawPayload)`。JSON 语义比较的好处是键顺序与空格差异都不影响判定，正好等于「同一份报文」。

2. **Windows + Docker Desktop 下 `docker compose build` 会命中过期缓存**：改了后端源码后构建输出全是 `CACHED`（连 maven 编译层都 CACHED），镜像创建时间却是新的 → 容器里跑的还是旧代码。解决：`docker compose build --no-cache <service>`。**验证 jar 是否真含新代码**的办法：`docker cp <容器>:/app/app.jar ./tmp-app.jar`，再用 `logs/inspect-jar.mjs` 解压看常量字符串。

用户反馈：免疫注射虽然由机器录入，但疫苗是兽医操作注射器打的，「操作人」应该是人而不是机器；另外应该再有一列显示设备；项目里其他和疫苗页面一样的页面也要改。

**现状（数据画像）**：接入层各通道原本做兜底 `Payloads.str(data,"operator") == null ? ctx.deviceLabel() : ...`，而 `IngestContext.deviceLabel()` 返回 `设备编号 + " 自动采集"`。于是：
- `vaccine_record.operator` 2 条 = `INJ-001 自动采集`
- `ractopamine_test.operator` 14 条 = `READER-001 自动采集`
- `entry_inspection.inspector` 10 条 = `RFID-001 自动采集`
- `split_batch.operator` 6 条 = `SPLIT-001 自动采集`
- `temperature_log.recorder` 45 条 = `TEMP-001 自动采集`（温度是探头采集，本来无人工，属正常）

**用户拍板**：①缺操作人 → **转人工补录**（不拒绝、不拿设备名顶）；②设备信息 → 把原「数据来源」列**改造成「采集设备」列**。

**后端**（4 个服务，缺操作人一律转 `DispatchResult.manual`；`force` 放行时写「未记录」）
- `IngestContext.deviceLabel()` **删除**，新增 `deviceNo()`（只给「本来就是机器记录」的字段用，如温度 `recorder`）。
- `ingest-service` 五个 handler：`VaccineChannelHandler`(operator)、`RactopamineChannelHandler`(operator)、`EntryChannelHandler`(inspector)、`SplitChannelHandler`(operator)、`ReceiptChannelHandler`(receiver，原本已有转人工，只换掉兜底值)；`TagChannelHandler` 只去掉设备名兜底（`pig_individual` 无 operator 列，业务侧本就忽略该字段，不阻断）。
- `TemperatureChannelHandler`：`recorder` 由 `deviceLabel()` 改为 `ctx.deviceNo()`。
- 业务侧兜底值 `"设备自动采集"` → `"未记录"`：`BreedingDeviceIngestService`(疫苗)、`SlaughterDeviceIngestService`(查验/瘦肉精)、`DistributionDeviceIngestService`(分割)。温度 `setRecorder` 的兜底保留（那条本来就是设备）。

- 8 个页面把「数据来源」列改成「采集设备」列（设备编号直显，tooltip 保留）：`farm/VaccineTable`、`slaughter/EntryTable`、`slaughter/RactoTable`（原先没有该列，新增）、`slaughter/InspectTable`、`slaughter/StampTable`、`distribution/StoreReceipt`、`distribution/SplitBatch`（详情）、`sales/SaleRecords`、`distribution/TransportMonitor`；人名列统一加 `|| '未记录'`；详情弹窗同步「采集设备」项。

- `IngestMonitor` 模拟上报补必填字段：ENTRY 加 `inspector`、RACTOPAMINE 加 `operator`、SPLIT 加 `operator`、VACCINE 的 `operator` 与 RECEIPT 的 `receiver` 改为必填；`fillSample` 相应填「张查验／赵检测／陈分割／刘兽医」；placeholder 由「留空记设备」改为「机器不得代签」类措辞。
