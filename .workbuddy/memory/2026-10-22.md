## 一、冷链温度定时自动打卡（10:25–11:05）

**需求**：用户确认此前没有定时采温（温度只靠设备推、系统不轮询），要求「发车后固定间隔自动打卡，送达后结束」。

**结论/口径**
- 之前确实没有：`ingestTemperature` 只收设备推送，且要求 status=2；库内在途单温度为 0 条。
- 新增定时采集：采集窗口 = **status=2（已发车且尚有站点未到达）**——运单状态由站点汇总推导（全部到达→3、全部签收→4），所以「车在跑」与 status=2 是同一件事，不需要开关也不会签收后还在写。
- **真机优先**：运单只要有过 `source=DEVICE` 记录，模拟采集对它永久停手（不混数据）。
- **不补历史**：错过的间隔就是空白，靠 gap_seconds/is_gap 标出来；一次补十条=替探头编造没采过的数据。
- 读数 `source=SIMULATED`/`recordMethod=AUTO`/`recorder=模拟探头`，前端标红 tag「模拟探头」+ tooltip「不代表真实车厢温度」；**刻意不编越界值**（-18~-16 正弦缓变，按运单号错相位）。
- 配置：`distribution.temperature.auto-sample.{enabled,interval-seconds=300,scan-interval-ms=30000}`。

**改动**
- 新增 `support/TemperatureRecorder`（越界/断档/间隔固化**唯一口径**，设备上报与定时采集共用）；`DistributionDeviceIngestService.ingestTemperature` 重构为调它（删掉类内重复判定与两个 @Value 字段）。
- 新增 `service/TemperatureAutoSampler`（@Scheduled，DistributionApplication 加 @EnableScheduling）；控制器加 `POST /distribution/internal/temperature/sample?force=true`（force 记录 sourceRef 带 `#force` 后缀，回归收尾精确删）。
- 前端：`SOURCE_LABELS/TAGS` 加 SIMULATED；TransportMonitor 温度记录卡头加「自动采集 · 每 X」（取最后一条固化的额定间隔），采集设备列 tooltip 区分 DEVICE/SIMULATED。

**踩坑**
- Edit 重复插入字段 → `variable temperatureRecorder is already defined`（javac 因它早退 → Lombok 没跑 → 满屏 getter 假错误；真错只有一条）。
- 构建-启动红线又中一次：force 参数是镜像 build 启动后才改的 → 重建第二次。

**验证**
- `verify-temp-auto.mjs` 27/0 + `verify-temp-auto-db.sh` 9/0（含 7 条不变量：间隔固化/读数区间/不混真机/送达后不新增/不补历史/近 10 分钟只来自运输中单/#force 清理）。
- 实测定时落点：10:40:57 → 10:46:08（310s）→ 10:51:38（329s），容器日志 `temperature_auto_sample written=2 scanned=3`（第 3 张是真机让位单）。
- 既有回归全绿：temp-gap-db 34/0（重构未破坏设备路径）、reconcile 18/0、channel-label、stage-order、store-scope 36/0、dashboard-roles 140/0、batch-receipt 27/0。
- 截图 `page-temp-auto.png`/`page-temp-records.png`（曲线 3 点、模拟探头 tag、当前温度 -16.0℃ 正常）。

**顺手修**
